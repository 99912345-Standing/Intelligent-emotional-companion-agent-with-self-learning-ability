# 架构说明

## 进程与边界

```
┌────────────────────────────────────────────────────────────┐
│ Electron 主进程 (src/main)                                  │
│  配置 / 日志 / 会话 / Hermes 记忆 / 连续权重 / 学习闭环       │
│  Agent 编排（主模型 + 工具循环 + Helper 子模型）              │
│  QQBridge (OneBot v11) · PhoneService · ComputerService      │
│  PluginHost（可编辑 JS 插件） · McpManager（stdio/HTTP）      │
└───────────────┬───────────────────────────────┬────────────┘
                │ IPC（preload 白名单）           │ 子进程
┌───────────────▼──────────────┐    ┌────────────▼─────────────┐
│ 渲染层 src/renderer           │    │ mcp-phone.bundle.mjs     │
│ 无框架 HTML/CSS/JS            │    │ mcp-computer.bundle.mjs  │
│ 不直接访问 Node/文件/网络      │    │ 独立 MCP stdio 服务       │
└──────────────────────────────┘    └────────────┬─────────────┘
                                                  │
                              ┌───────────────────▼─────────────┐
                              │ ADB / Windows PowerShell         │
                              │ 真机 / AVD / 桌面                │
                              └─────────────────────────────────┘
外部：
  SnowLuma OneBot HTTP/WS  ←→  QQBridge  ←→  Agent Core
  模型 API（OpenAI/Anthropic/本地）
  Bing / 公网信源
```

- **UI 无 Node 权限**：`contextIsolation: true`、`nodeIntegration: false`；所有能力通过 `preload.cjs` 的 `invoke` 进入主进程处理器。渲染层的链接只允许 http/https，统一交给系统浏览器。
- **本地优先**：`initPaths()` 在 `app.ready` 前固定 `userData`、`sessionData`、`crashDumps`，全部位于工作目录 `data/`。
- **媒体协议**：`banxing-media://local/...` 仅允许读取工作目录内文件，拒绝路径穿越。
- **打包**：`electron-builder` portable；插件/MCP/qq-bridge/ADB/docs 作为 extraResources，首次运行由 `seedWorkspace()` 播种到 exe 同目录。

## Agent 轮次

1. 写入用户消息与会话。
2. 更新连续权重（每条消息）；抽取关系记忆；必要时建立/更新工作轨迹。
3. Hermes 插件 hooks；构建五层记忆上下文。
4. 空白识别：
   - 明确事实问题 → 同步执行学习闭环，拿到来源后重建上下文。
   - 用户质疑 → 后台复核，主回答明确“复核中”。
5. 视觉路由：主模型视觉已验证则直接传图；否则由 Helper 观察后以文字注入。
6. 调主模型（带工具 schema）。工具循环最多 7 轮：
   - 记忆/关系/工作日志
   - 联网搜索、网页读取、学习闭环
   - `ask_helper`
   - 手机、电脑、QQ 发送
   - MCP 工具、插件工具
7. 保存最终回答、工具轨迹、权重快照；返回 UI/QQ。
8. 每 12 次权重事件触发内部反思。

## 分层记忆

| 层 | 文件 | 特点 |
|---|---|---|
| 知识库 | `data/memory/knowledge.jsonl` | 事实、时间、来源、置信、revisions、冲突标记 |
| 关系记忆 | `data/memory/relationship.jsonl` | 偏好/情绪/画像/边界，独立且高优先级 |
| 工作日志 | `data/memory/worklogs.jsonl` + `active-work.json` | 进行中任务，闲置阈值自动归档 |
| 权重轨迹 | `data/memory/weights.jsonl` + `weight-state.json` + `weight-anchors.jsonl` | 三线前后值、触发词、时间衰减、话题锚点 |
| 多模态 | `data/memory/multimodal.jsonl` + `media/` | 图片/音频/语音/截图/文件 |
| 人物印象 | `data/people/people.jsonl` | QQ/昵称、亲近度、动态印象、手动锁 |

知识写入带 `verifiedAt`、`staleAfterDays`、`validUntil`、`sources[].score`。`markStaleEntries()` 只标记过时，不修改事实本体。编辑/复核通过 `revisions` 留痕。

检索不是向量数据库：当前版本使用中英文字符 bigram + 词项覆盖、置信度、时效的混合评分。关系层按 `personId` 隔离，并接受本轮 `priority`：陪伴维高时关系记忆取更多，工作/学习维高时知识库取更多。数据量达到数万条时可把 `JsonlStore` 替换为 SQLite + FTS/向量索引，接口不变。

## 连续权重

- 状态向量：`work` / `companion` / `learning` 三维连续值，归一化总和为 1；UI 显示百分比。
- 词项词典 + 强信号正则产生三维信号与 salience；目标维度有独立的强事件阈值。
- 快变量：强信号把目标维度抬到 `highThreshold` 以上、其他维度抬到 `otherBaseline`，再归一化；其他维度只被压低，不会被清空。
- 慢变量：`decayTo()` 按每个维度的 `baseline + (w-baseline) * exp(-Δt/τ)` 指数衰减；工作/陪伴/学习半衰期默认 20/90/45 分钟。baseline 非零。
- 冷却与迟滞：`eventCooldownSec` 内同向事件不重复触发；反向触发需要 `reverseConfidenceThreshold` 以上。
- 话题锚点：工作/学习信号写入 `weight-anchors.jsonl`；`findAnchor()` 用 token 相似度 + “继续/刚才/上次”线索命中，恢复当时的向量并加载工作日志摘要。
- 结果不直接进入系统提示，也不包含百分比。`WeightEngine.behaviorBlock()` 把当前倾向翻译成定性表达取向，并提示模型可通过 `weight_read` 查看定性状态、`weight_tune` 做有冷却和上限的小幅修正。没有 `weight_status` 原始数值工具；数值仅供 UI 与内部调度。

## 自学习闭环

`LearningEngine.run()` 的状态机：

```
blank → search → fetch → score → validate → archive
```

- 查询：原始问题 + 时效/官方变体 + `site:gov.cn OR site:edu.cn`（最多 3 组）。
- 搜索适配器：Bing RSS（默认）、SearXNG JSON，DuckDuckGo HTML 兜底。
- 安全抓取：协议白名单、DNS 解析后拒绝内网、手动重定向校验、3MB 限制、正文提取。
- 信源分：域名层级 + 相关性 + 正文可读性 + 时效 + 独立域名交叉印证。
- 验证：有主模型时输出约束 JSON（answer/claims/conflicts/confidence/recommendation）；失败/无模型时启发式降级。
- 归档阈值：`archiveConfidence` + 最少独立域名；不达标写入 candidate。
- 无主模型参与综合时（启发式降级），无论置信度多少都只写 candidate，不覆盖旧 active 记忆。冲突双方保留并互链。
- 命中 active 但已超过时效窗口的知识时，Agent 会在回答前先触发该条目的重新核验（`staleHit` 分支），把最新核验时间/来源注入本轮；若复核失败，会在回答中明确“旧资料、无法保证当前仍正确”。记忆页提供最多 5 条的批量复核。

## qq-bridge / SnowLuma

```
QQ ←— SnowLuma Hook —→ SnowLuma OneBot HTTP/WS
                             │
                    QQBridge (src/main/qqbridge.js)
                    ├─ 自动发现端口/token：vendor/qq-bridge/src/snowluma-conn.js
                    ├─ 白名单：owner / allow / deny / 群 @ 限制
                    ├─ 图片/语音 → 多模态记忆
                    ├─ 入站消息 → Agent Core → 回复
                    └─ 出站：OneBot HTTP，脱敏 + 分段
```

- qq-bridge 上游的主进程依赖 DSH Web 协议，不能直接指向本项目 Agent；因此本应用只复用其 QQ 侧连接发现与安全语义，保留完整上游源码以便对照/替换。
- SnowLuma 是独立第三方运行时，exe 不包含它，也不自动安装/扫码。应用仅通过 OneBot 协议连接，不修改 QQ 进程。
- WS 与 HTTP token 可能不同：自动模式会扫描 `integrations/SnowLuma/config/onebot_<QQ号>.json` 并探测哪个 token 可用；**手动 OneBot 模式**完全跳过 SnowLuma 配置发现，直接使用 UI 中填写的 WS/HTTP 地址与两个独立 Token，支持 NapCat/Lagrange/LLOneBot/go-cqhttp/SnowLuma。
- **QQ 主对话**：`qq.primaryConversation=true` 时，主人 QQ 私聊的 Agent channel 映射为 `desktop`，与桌面主对话共用记忆/权重；桌面 UI 发出的回答由 main 通过 OneBot HTTP 回写主人。只回写回答，不伪装发送用户原话。
- 真实 Agent 返回结构是 `{userMessage, assistantMessage}`；QQBridge 兼容旧的 `{content}` 测试桩，避免“有回复但发不出去”的静默失败。

### 三线连续状态向量

`WeightEngine` 的 state 是 `[work, companion, learning]` 三维归一化向量：

- **快变量**：强信号检测器输出目标维度与 salience。目标维度至少抬到 `highThreshold`（默认 0.7）并略高于其他维度，其他维度抬到 `otherBaseline`（默认 0.3），再归一化；`0.7` 是归一化前的原始强度，不是最终 UI 百分比。工作上下文保留在后台。
- **慢变量**：`decayTo()` 对每个维度按 `baseline + (w-baseline) * exp(-Δt / τ)` 指数衰减；`τ = halfLife / ln2`。工作半衰期 20 分钟、陪伴 90 分钟、学习 45 分钟；baseline 非零（工作 0.3 / 陪伴 0.4 / 学习 0.3）。
- **冷却与迟滞**：`eventCooldownSec` 内同向高事件不重复触发；反向触发需要 `reverseConfidenceThreshold` 以上。
- **话题锚点**：工作/学习信号写入 `weight-anchors.jsonl`；`findAnchor()` 用话题 token 相似度 + “继续/刚才/上次”等线索命中，恢复当时的三维权重。
- **5 小时转存**：`worklogTransferMinutes=300` 时，active work 压缩为工作日志并写入锚点；工作维度只回基线，不归零。
- **学习维度**：学习信号会触发 knowledge gap/research；`completeLearning()` 把学习维度拉回 baseline。
- **检索优先级**：`MemoryEngine.buildContext()` 接收 priority；陪伴高取更多关系记忆，工作/学习高取更多知识记忆。

### 权重 AI 微调

- 主模型能读取 `weight_read` 的定性状态，不含百分比；`weight_tune` 接受 `work/companion/learning/balance` 方向与 0.01-0.06 的力度，默认 20 秒冷却。
- 微调会写入 `eventType='ai_tune'` 的历史；它不能修改用户设置、活动模式或角色边界。

### 群聊 / 私聊活跃度与主动话题

- 群聊和私聊各有独立模式：`manual` 使用用户滑杆值；`ai` 由后台根据信号计算有效值，配置里的值只作为基础/切回手动时的起点。
- 群聊 AI 值：最近 10 分钟群消息热度映射到 8–50%；`groupCooldownSec` 按群记录发送冷却，@ 始终优先。
- 私聊 AI 值：按当前陪伴/工作权重差映射到 0–60%；`privateIdleMinutes` 要求安静达到阈值，`privateMinIntervalMinutes` 限制两次主动之间的最短间隔。
- UI 用两个独立卡片和滑杆展示；AI 模式下有效值由 `qq:activity` 事件更新，拖动滑杆会自动切回手动。AI 主模型不读取这些数值。
- `QQBridge.maybeProactive()` 在调度器里检查连接、白名单、安静阈值和概率；`Agent.proactiveTurn()` 先让模型选一个不涉及隐私的可检索主题，再按开关走学习闭环、读取手机界面，最后生成 1-3 句自然消息。主动消息标记 `proactive:true` 并写回会话。
- 主动话题不使用用户原话伪装发送；默认 `privateActivity=0`，只有用户显式开启后才会发生。

### Token 用量统计

- `ModelClient.discoverModels()` 根据协议请求 OpenAI `/v1/models` 或 `/models`（失败自动回退）、Anthropic `/v1/models`，携带 Bearer / `x-api-key`；保留返回的 `input_modalities`、`context_window` 等元数据，前端不提供自由文本模型名输入。官方 DeepSeek V4.1 Flash 的 ID 为 `deepseek-flash`，`input_modalities` 包含 `image`。
- `ModelClient.request()` 将 OpenAI/Anthropic 的 usage 规范化为 `prompt/completion/total/cached/cacheMiss`；缺少 usage 时按文本长度估算并标记 `estimated`。
- Prompt cache：稳定人格/工具/工作方式放在 system 前缀；时间、人物印象、三线取向、记忆和查证状态放到本轮 user 尾部。会话历史消息只保存原始 user/assistant，不保存动态上下文，避免每轮把整段前缀打散。
- 搜索：`WebSearch.search()` 并行尝试 Bing RSS/HTML、DuckDuckGo HTML/Lite、Wikipedia；正文抽取优先 article/main 并清理脚本/导航/页脚。用户消息中的 URL 会先经 `fetchReadable()` 注入正文。
- 表情包：`resources/stickers` 的 manifest + PNG 由 `QQBridge.sendSticker()` 发送；QQ `mface` 以 `kind=sticker` / `tags=['表情包']` 写入多模态记忆，`stickerMemory()` 搜索，`sendStoredMedia()` 从记忆读取并发送，均使用 OneBot `image` 段（base64），只允许当前白名单会话。
- Hermes：`plugins/hermes` 注册 `hermes_recall` / `hermes_remember` / `hermes_reflect` / `hermes_growth`；启动时只迁移旧 `harmes` 插件 ID。
- 角色自迭代：`Agent.maybeCalibratePersona()` 在稳定核心证据足够时调用 `PersonaEngine.calibrate()`；`persona_self_update` 是显式工具入口。护栏仍要求稳定核心、情绪冷静期、冷却、次数上限与锁。
- QQ 并发：`QQBridge.enqueueBatch()` 以 900ms 窗口缓存，`chooseBatch()` 打分选一条；`flushBatch()` 把其余消息作为 `meta.batch` 上下文，不逐条回复。`sendAuto()` 支持 `reply` 段引用。
- 多模态插槽：`multimodal.slots` 五项（vision/ocr/audio/document/imagegen）可路由 primary/helper；`multimodal_task` 返回观察结果给主模型。
- 日记：`DiaryEngine` 写入 `data/diary/diary.jsonl`；Agent `diary_write`/`diary_read` 与 UI 共用。
- 音乐：`MusicService` 使用网易云公开搜索/歌词 API 与可选 NCM PC CDP；本地 SAPI 生成 WAV。Agent 工具 `music_now/music_lyrics/music_sing`；QQ 语音走 OneBot `record`。
- 多模态自定义端点：每个 slot 可配置 baseUrl/protocol/model/apiKey，`multimodal_task` 用临时 `ModelClient` 调用，结果返回主模型。
- 内容边界：`content-policy.js` 的 `reviewIdleQuery()` 对自由选题做四项审查（安全范围、隐私、高危、空泛古怪），不通过时 `suggestIdleQuery()` 回退到预设安全方向；搜索/正文/知识写入再做四层过滤。`isEmotionalTopic` 只把人类情感/关系主题判为情感材料，AI/模型/技术类情感研究仍归知识。
- 人格演化：`buildSystemPrompt()` 使用数字躯壳/模糊记忆/人的节奏模块；`embodied.js` 包装工具异常；`MemoryEngine.buildContext()` 加时间滤镜；`PersonaEngine` 的 `emotional-memory.jsonl` → `layerEmotionalMemory()` → `emotionLine` 是唯一情感线来源，AI 不能直接写情感线；默认 `aiMinSpanDays=0`、`aiCooldownHours=0`。
- 闲时自学习：`idleLearning` 配置 60 分钟空闲、5 分钟检查、180 分钟冷却、每日 4 次、0–7 点静默，均由 `idle:save` 校验并热重载检查定时器。情感主题 `archive:false` 后写入第一人称情感记忆，知识主题 archive 到知识库，避免双写。`maybeIdleLearn()` 使用 `qq.lastWhitelistActivityAt`、`agent.suggestIdleQuery()`、`learning.run({trigger:'idle'})`；`agent.recordIdleLearning()` 调用 `persona.recordEmotionalMemory()`；页面 `idle:overview` 聚合 cycles/knowledge/emotional journal。
- 搜索：`search.providers` 支持 bing/duckduckgo/wikipedia/baidu/sogou/searxng；`BrowserCrawler` 启动本机 Edge/Chrome `--headless`，通过 CDP 提取渲染后的正文、链接和 `video` 标签。`web_video` 使用 `fetchReadable` 的 og:video 元数据，非 m3u8 可下载到 `data/memory/media`，并写知识候选。
- `UsageStore` 写入 `data/usage/events.jsonl`，记录 role/model/channel/purpose/latency/memoryHits。
- 聚合页：今日与最近 7 天、缓存命中率、记忆命中率、上下文窗口占比、按对话/模型/角色拆分、最近 30 次调用。
- 缓存命中率只在服务返回缓存字段时计算；记忆命中率按本轮是否召回至少一层记忆计算。

### 人物账本 / 亲近度 / 印象

`src/main/people.js` 以 `personId = qq:<QQ号>` 为稳定主键，群聊与私聊合并到同一份 `data/people/people.jsonl`：

- `nickname` 是显示名，`aliases` 保存旧昵称；QQ 号不变、昵称变化时刷新关系记忆的 `nickname` 字段，不新建人物。
- `affinity` 由对话中的正向/负向信号缓慢变化；`manual=true` 时停止自动更新。
- `impression` 由 `refreshImpressions()` 根据最近发言生成（模型优先，无模型时规则回退），每 5 分钟处理 dirty 人物；UI 可手动刷新。
- `Agent.personBlock()` 把当前对话对象的昵称、亲近度和印象注入 system prompt，让这些设定真实影响称呼、距离感和主动程度。
- 关系记忆带 `personId` / `nickname`；`MemoryEngine.buildContext(query, {personId, priority})` 只取该人的记录（加全局记录），并按三线状态调整关系/知识检索权重，避免群聊/私聊串记忆。

### 记忆手动修正

- 关系记忆：`memory:updateRelationship`，保留 `editedBy=user`。
- 进行中的工作：`memory:updateActiveWork`；已归档工作日志：`memory:updateWorklog`。
- 多模态：`memory:updateMedia` 修正 caption/tags，`memory:deleteMedia` 删除记忆记录（可选择是否删文件）。
- 知识条目仍可编辑并保留 revisions。所有修正立即影响检索，不等待重启。

### QQ 拟人化发送

`QQBridge.sendAuto()` 先通过 `naturalizeQqText()` 清理 Markdown/标题/列表，再按文本长度计算首次等待；尝试调用 OneBot `set_input_status`（部分实现支持），然后分条发送，条间随机停顿。深夜时段按 `quietFactor` 放慢。`humanize.enabled=false` 时回退到固定 `sendDelayMs`。

### 桌面截图

`ComputerService.screenshot()` 与电脑 MCP 都只写入 `data/computer/screenshots/`，返回当次 `dataUrl`；不调用 `memory.saveMedia`，因此不会出现在多模态记忆里。手机截图仍按多模态记忆保存。

### 角色稳定性护栏

`PersonaEngine` 在 AI 修改前做多层校验：

- 证据只取主人/全局关系记忆，群聊其他人的印象不会进入角色校准。
- 至少 `aiMinEvidence`（默认 3）条真实证据，至少一条稳定核心（知识/偏好/边界/工作日志）；情绪事件不能单独改人设，且数量不能多于稳定证据。
- 证据跨度至少 `aiMinSpanDays`（默认 3 天）。
- 最近有强烈情绪事件时，`emotionLine` 至少冷却 `aiEmotionalCooldownHours`（默认 24 小时）。
- AI 修改有 `aiCooldownHours`（默认 72 小时）和 `aiMaxRevisions7d`（默认 2 次）限制。
- `aiLocked` 可由用户关闭；`rollback()` 回滚上一版；所有修改保留 revisions。
- 这些限制只约束 AI；用户手动编辑仍然直接生效，但会留下 user 修订记录。

## 角色双线

`src/main/persona.js` 维护：

- 固定：名字、角色、关系、安全边界。
- 可编辑：`knowledgeLine`（求真方式）与 `emotionLine`（陪伴方式）。
- 证据：修改必须可引用知识/关系/反思/工作日志/多模态 ID；AI 修改强制要求至少一个有效 ID。
- 修订：`data/persona/profile.json` + `data/persona/revisions.jsonl`（before/after、by、reason、evidence）。
- 注入：每次对话把两条线与边界放进 system prompt；AI 可通过 `persona_read` / `persona_update` 在对话中自行小步维护。
- 校准：UI 可显式触发一次模型校准，模型只能提出 JSON；服务端验证证据后才落盘。

## 手机 / 电脑

- `PhoneCore`（`src/shared/phone-core.js`）只使用 `child_process.execFile` 调 ADB，无 shell 拼接；坐标与包名做格式校验；截图先落在设备再 pull，避免 Windows 二进制管道 CRLF 损坏。
- `mcp-phone.js` 用 MCP SDK 对同一核心暴露工具；单文件 bundle 由 esbuild 生成。
- `ComputerService` 调用 `mcp/computer/desktop.ps1`，通过环境变量传参，避免把用户文本拼进 PowerShell。`SendInput` 使用 Unicode 扫描码，支持中文输入。
- 手机截图进入多模态记忆；桌面截图写入 `data/computer/screenshots/` 仅作当页临时查看，不进入多模态；电脑 Shell 需要两个开关同时开启。

## 文章抓取与对照

- 两篇小黑盒分享页由客户端渲染，静态请求只能拿到 SPA 壳。
- 使用 Edge Headless 渲染并保存 DOM，再用 BeautifulSoup 提取文本；原文在 `docs/articles/`，精读与抓取命令在 `docs/articles/README.md`。
- 文章对应仓库 `pinganbbOvO/ai-companion-kit`（MIT）已完整放在 `vendor/ai-companion-kit`，其 `transport-onebot.js` 证明了 OneBot v11 通用连接的设计；本项目采用 @snowluma/sdk 的 WS 客户端 + HTTP API 实现手动模式，保留自动发现。
- 文章强调的“角色卡 / 多线”“按人存记忆”“健康检查”“手机 MCP / ADBKeyboard / 备用机”分别映射到 PersonaEngine、关系记忆层、只读检查、PhoneCore/mcp-phone。
- 未将主动发消息、日记自动写、网易云耳朵、QZone 连招设为默认行为，避免外部副作用；这些是可插扩展，不是本次核心闭环。

## 扩展点

- **插件**：`PluginHost` 动态 import；工具名冲突检测；权限字段需在允许集合内。
- **MCP**：UI 配置 stdio/HTTP；支持 `${ROOT}`、`${TOOLS}`、`${HOME}` 占位符；自动注入 `BANXING_HOME`。

## 打包与运行

- `npm run build:mcp` 先打包两个 MCP 服务。
- `electron-builder --win portable` 产出 `dist/伴行Agent-1.0.0-portable.exe`。
- 应用根目录由 `PORTABLE_EXECUTABLE_DIR`（便携）/ exe 所在目录决定；`seedWorkspace()` 补齐可编辑扩展。
- 只读检查由 ASCII 的 `检查环境-只读.bat` 启动，实际逻辑在同目录 `check-readonly.ps1`；打包资源中保留同一对文件，UI 通过 `cmd.exe` 调用同一入口。`app.checkOnStart` 为真时启动 8 秒后静默检查一次，失败才提示。
- 分离 BAT 与 PS1 的原因：cmd 在 UTF-8 代码页下解析含中文的长 BAT 行时可能产生伪错误；BAT 保持 ASCII，中文输出全部交给 PowerShell。
- `启动伴行.bat` 会清掉 `ELECTRON_RUN_AS_NODE`/`ELECTRON_NO_ATTACH_CONSOLE`，避免从开发终端启动时把 GUI 变成 Node 进程。
